# Власна копія EdgeKnow для вашої команди

> **Чернетка.** Так інструкція виглядатиме після доопрацювань з «Плану робіт після пілоту» (SPEC). Зараз ці кроки ще не працюють. У фінальній версії після кожного кроку буде скріншот (📷).

## Що це і навіщо

EdgeKnow — це вікі для команди. Ним можна користуватися двома способами:

- **Спільний сервіс.** Заходите на сайт EdgeKnow і працюєте, нічого не налаштовуючи.
- **Власна копія.** Про неї ця інструкція. Ви робите для команди окремий, свій сайт EdgeKnow. Він повністю ваш: ніхто інший не має доступу до вашого сайту, бази даних і файлів, і ви ні від кого не залежите.

Для власної копії знадобляться чотири безкоштовні сервіси. Ось що робить кожен:

| Сервіс | Простими словами |
|---|---|
| **GitHub** | Сховище коду. Там лежатиме копія «програми» вашої вікі. Самі ви в неї заглядати не будете. |
| **Vercel** | Сервіс, який запускає вашу вікі як сайт в інтернеті і дає їй адресу. |
| **Supabase** | База даних: тексти сторінок, коментарі, хто має доступ. |
| **Google Cloud** | Вхід через Google-акаунт і зберігання зображень на вашому Google Drive. |

Усі сервіси безкоштовні. Банківська картка ніде не потрібна: якщо десь просять картку, ви зайшли не туди, див. «Якщо щось не так».

## Перед початком

- **Комп'ютер** (не телефон) з браузером Chrome, Edge, Firefox або Safari.
- **Google-акаунт власника команди.** Якщо в компанії Google Workspace (пошта на кшталт `ім'я@компанія.com`), краще взяти його.
- **Доступ до своєї пошти:** сервіси надсилатимуть листи для підтвердження.
- **45–60 хвилин** без поспіху. Якщо доведеться перерватися, нічого не зламається: просто продовжте з того кроку, де зупинилися.

**Порада:** заведіть собі нотатку або документ. Будемо записувати туди кілька значень, щоб нічого не загубити.

## Крок 1. Акаунт GitHub (5 хв)

Тут Vercel зберігатиме копію програми вашої вікі.

1. Відкрийте **https://github.com/signup**.
2. Введіть пошту, придумайте пароль і ім'я користувача (латиницею, наприклад `our-team-wiki`) → **Continue**.
3. Пройдіть перевірку «я не робот».
4. На пошту прийде код. Введіть його на сторінці.
5. Якщо GitHub запропонує обрати тариф, оберіть **Free**. Якщо питатиме, чим займаєтеся, можна натиснути **Skip**.

✅ **Готово, коли:** ви бачите головну сторінку GitHub і свій аватар у правому верхньому куті.

Більше на GitHub нічого робити не треба. Вкладку можна закрити.

## Крок 2. Кнопка «Deploy»: створюємо сайт (10 хв)

**Де кнопка:** на сторінці **https://edge-know.vercel.app/self-host**. Там коротко про власну копію і велика кнопка **▲ Deploy**. Шукати щось на GitHub не потрібно.

1. Відкрийте **https://edge-know.vercel.app/self-host** і натисніть **▲ Deploy**. Відкриється сайт Vercel.
2. **Ви побачите:** «Sign up / Log in to Vercel». Натисніть **Continue with GitHub**.
   - Якщо Vercel питає про тариф, оберіть **Hobby** (безкоштовний). Введіть своє ім'я → **Continue**.
   - GitHub запитає дозвіл для Vercel: **Authorize Vercel**.
3. **Ви побачите:** сторінку **«You're almost done»** з розділом **Create Git Repository**. Тут Vercel кладе копію програми на ваш GitHub.
   - **Git Scope:** ваше ім'я з GitHub (вже обране).
   - **Repository Name:** залиште `edgeknow` або впишіть свою назву латиницею, наприклад `our-wiki`. Ця назва стане частиною адреси сайту.
   - Галочку **Create private Git Repository** залиште увімкненою.
   - Натисніть **Create**.
   - Якщо GitHub попросить дозволу: **Install** → **All repositories** → **Install**.
4. **Ви побачите:** розділ **Add Integrations → Supabase**. Тут Vercel створює базу даних.
   - Натисніть **Add**.
   - Погодьтеся з умовами (**Accept**) і оберіть тариф **Free**.
   - **Project name:** будь-яка назва, наприклад `our-wiki`.
   - **Region:** найближчий до команди. Для України — **Frankfurt (eu-central-1)**.
   - **Database password:** натисніть **Generate** і запишіть пароль у свою нотатку. Скоріше за все він вам ніколи не знадобиться, але нехай буде.
   - Натисніть **Create** і зачекайте близько хвилини, поки з'явиться галочка.
5. Натисніть **Deploy** і зачекайте 3–5 хвилин. На екрані бігтимуть рядки тексту: це нормально, нічого читати не треба.
6. **Ви побачите:** конфетті 🎉 і «Congratulations!». Нижче — зменшене зображення вашого сайту.
   - Натисніть **Continue to Dashboard**.
   - У блоці **Domains** знайдіть адресу сайту, наприклад `our-wiki.vercel.app`, і запишіть її в нотатку.

✅ **Готово, коли:** у вас записана адреса сайту.

## Крок 3. Відкриваємо свій сайт (2 хв)

1. Відкрийте адресу сайту з кроку 2 у **новій вкладці**. Цю вкладку не закривайте до кінця інструкції.
2. **Ви побачите:** сторінку **«Перше налаштування»** з трьома пунктами: База даних ✅, Вхід через Google ⏳, Власник ⏳.
3. У блоці **«Вхід через Google»** є три адреси, кожна з кнопкою **Скопіювати**. Вони знадобляться на кроці 4.

Сторінку налаштування бачить лише той, хто відкриває сайт першим, поки ним ще ніхто не володіє. Тому пройдіть інструкцію до кінця за один день.

## Крок 4. Вхід через Google (20 хв)

Це найдовший крок, тут найбільше кнопок. Робіть його повільно, пункт за пунктом. Будьте уважні: Google часом трохи змінює назви кнопок, тож шукайте схожі.

### 4.1. Створюємо проєкт у Google Cloud

1. Відкрийте **https://console.cloud.google.com** і увійдіть тим Google-акаунтом, який обрали на початку.
2. Якщо ви тут уперше, з'явиться вікно привітання. Оберіть країну, поставте галочку згоди з умовами → **Agree and continue**.
3. Угорі зліва, поруч із логотипом **Google Cloud**, натисніть кнопку з написом **Select a project** (або з назвою якогось проєкту).
4. У вікні праворуч угорі натисніть **New project**.
5. **Project name:** наприклад `Our wiki`. Решту не чіпайте → **Create**.
6. Зачекайте 10–20 секунд. Праворуч угорі з'явиться дзвіночок із повідомленням. Натисніть у ньому **Select project**.

✅ **Готово, коли:** угорі зліва написано назву вашого проєкту.

### 4.2. Дозволяємо доступ до Google Drive

1. У пошуку вгорі сторінки введіть **Google Drive API** і оберіть результат з таким самим заголовком.
2. Натисніть синю кнопку **Enable**.

✅ **Готово, коли:** кнопка змінилася на **Manage** або **Disable API**. Це означає, що Drive увімкнено.

### 4.3. Налаштовуємо вікно входу

Це вікно Google показує людям, коли вони входять у вашу вікі.

1. У пошуку вгорі введіть **Google Auth Platform** і відкрийте її.
2. Натисніть **Get started**.
3. **App Information:**
   - **App name:** назва вашої вікі, наприклад `Our wiki`. Її бачитимуть люди під час входу;
   - **User support email:** оберіть свою пошту зі списку;
   - **Next**.
4. **Audience:**
   - **Internal**, якщо ви в Google Workspace компанії: тоді входять лише колеги з вашої компанії. Пункт буде недоступний, якщо у вас звичайна пошта @gmail.com;
   - **External** в усіх інших випадках;
   - **Next**.
5. **Contact Information:** ще раз ваша пошта → **Next**.
6. **Finish:** поставте галочку згоди → **Continue** → **Create**.
7. **Тільки якщо ви обрали External:** зліва відкрийте **Audience** → **Publish app** → **Confirm**. Без цього увійти зможете лише ви.

### 4.4. Створюємо «ключ» для входу

1. Зліва відкрийте **Clients** → угорі **+ Create client**.
2. **Application type:** оберіть **Web application**.
3. **Name:** будь-яке, наприклад `Wiki`.
4. **Authorized JavaScript origins** → **+ Add URI**: вставте **адресу 1** зі сторінки налаштування вашого сайту (крок 3). Перейдіть на вкладку сайту → **Скопіювати**, поверніться сюди → вставте (Ctrl+V, на Mac Cmd+V).
5. **Authorized redirect URIs** → **+ Add URI**: вставте **адресу 2**. Потім ще раз **+ Add URI** і вставте **адресу 3**.
6. Натисніть **Create**.
7. **Ви побачите:** вікно **OAuth client created** з двома значеннями: **Client ID** і **Client secret**.
   - ⚠️ **Client secret Google показує лише зараз.** Скопіюйте обидва значення в нотатку (кнопка 📋 поруч із кожним) і лише потім закривайте вікно.
   - Якщо все ж закрили, не страшно: відкрийте клієнт, натисніть **+ Add secret** і скопіюйте новий секрет.

✅ **Готово, коли:** у нотатці записані Client ID (закінчується на `.apps.googleusercontent.com`) і Client secret (починається з `GOCSPX-`).

## Крок 5. Завершуємо на своєму сайті (5 хв)

1. Поверніться на вкладку свого сайту, на сторінку **«Перше налаштування»**.
2. У поля **Client ID** і **Client secret** вставте значення з нотатки → **Зберегти**.
3. Сайт перевірить налаштування. Зачекайте кілька секунд, поки «Вхід через Google» стане ✅. Якщо замість ✅ з'явиться ❌, під ним буде написано, що саме виправити.
4. Натисніть **Увійти через Google**.
   - Оберіть свій акаунт.
   - Якщо Google показує «Google hasn't verified this app» (Google не перевірив цей застосунок), натисніть **Continue**. Це ваш власний застосунок, тож усе гаразд.
5. Ви ввійшли і стали **власником** вікі. Тепер сайт запропонує:
   - **назвати свій workspace** (простір команди);
   - **підключити Google Drive** для зображень і резервних копій. Натисніть **Підключити**, оберіть акаунт і дозвольте доступ. Сервіс бачитиме на Drive лише ті файли, які створив сам;
   - **запросити колег:** за поштою або за доменом компанії.

🎉 **Готово!** Надішліть колегам адресу сайту. Усі подальші налаштування — у самій вікі: **⚙️ Налаштування workspace**.

## Оновлення

Коли виходить нова версія, власник бачить на сайті повідомлення **«Доступне оновлення»**. Натисніть **Оновити** і зачекайте 5 хвилин. Сайт і база оновляться самі, дані збережуться.

## Що безкоштовно і де межі

| Сервіс | Що там зберігається | Безкоштовний ліміт (орієнтовно) |
|---|---|---|
| Vercel Hobby | сам сайт | приблизно 100 ГБ трафіку на місяць — це десятки тисяч переглядів сторінок |
| Supabase Free | тексти, коментарі, доступи | 500 МБ — це тисячі сторінок |
| Ваш Google Drive | зображення, резервні копії | місце на вашому Drive |

- **Supabase:** якщо вікі ніхто не відкривав 7 днів, база «засинає». Сайт покаже, як її розбудити (кнопка **Restore** у панелі Supabase, 1 хвилина).
- **Vercel Hobby:** дозволене лише некомерційне використання.

## Якщо щось не так

| Що бачите | Що робити |
|---|---|
| Просять банківську картку | Ви обрали платний тариф. Поверніться й оберіть **Hobby** (Vercel) або **Free** (Supabase). |
| Деплой у кроці 2 завершився червоним **Error** | Натисніть **Redeploy**. Не допомогло — напишіть нам (кнопка «!?» на сайті EdgeKnow). |
| На сторінці налаштування ❌ біля «Вхід через Google» | Під ❌ написано, що не так. Найчастіше адресу скопіювали не повністю: перевірте крок 4.4. |
| «Error 400: redirect_uri_mismatch» під час входу | Адреси 2 і 3 вставлено з помилкою. Відкрийте Google Cloud → **Clients** → ваш клієнт і порівняйте їх зі сторінкою налаштування. |
| Колега бачить «Access blocked» | Ви обрали **External**, але не натиснули **Publish app** (крок 4.3, пункт 7). |
| Сторінка налаштування зникла посередині | Відкрийте `https://адреса-вашого-сайту/setup`. Вона доступна, поки у вікі немає власника, а після цього — тільки власнику. |

## Для розробки: що треба зробити, щоб інструкція стала такою

- **Публічна сторінка `/self-host`** на спільному сайті з кнопкою **▲ Deploy**. Кнопка — це посилання Vercel «clone» на відкритий репозиторій EdgeKnow з інтеграцією Supabase. Ту саму сторінку додати в довідку `/help`.
- **Інтеграція Supabase:** застосунок має приймати назви змінних, які вона дає.
- **Перевірити наживо:** чи створює інтеграція Supabase на Vercel базу без окремої реєстрації в Supabase.
- **Міграції бази** запускаються автоматично під час кожної збірки на Vercel.
- **Внутрішні секрети** (шифрування доступу до Drive, нічні задачі) виводяться із секретного ключа Supabase, тому вводити їх окремо не треба.
- **Майстер `/setup`:**
  - доступний лише поки немає власника;
  - показує три адреси для Google з кнопками «Скопіювати»;
  - зберігає Client ID і secret у налаштування входу Supabase та в сам сервіс;
  - вмикає перевірку нових користувачів;
  - перевіряє все разом;
  - робить першого, хто увійшов, власником;
  - зрозуміло пише про помилки.
- **Повідомлення «Доступне оновлення»** і оновлення копії з GitHub в один клік.
- **Скріншоти** до кожного кроку, зняті на чистих нових акаунтах.
- **Перевірити наживо:**
  - вікно «Google hasn't verified this app» для типу External з доступом лише до власних файлів (`drive.file`);
  - точні ліміти безкоштовних тарифів;
  - поточні назви кнопок у Vercel і Google Cloud.
- **Пройти інструкцію з людиною, яка ніколи не бачила цих сервісів,** і виправити всі місця, де вона зупинилась.
