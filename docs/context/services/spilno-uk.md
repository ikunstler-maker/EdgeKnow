# Spilno — CRM

> **Картка сервісу (запланований).** Читати разом із `docs/context/00-overview-uk.md`. **Стан на:** 2027-01-14. Коду ще немає: це задум і відкриті питання. Джерело правди — `docs/decisions.md`, `docs/backlog.md`.

## 1. Призначення

Клієнти, угоди й воронка продажів поруч із задачами й документами.

- **Стан:** ⏳ у планах; показано як «Скоро», окремого плану ще немає.

## 2. Задум (з лендінгу)

- Клієнти, контакти й історія спілкування.
- Угоди й воронка продажів на дошці.
- Задачі, документи й зустрічі з клієнтом — в одному місці.

## 3. Очікувані зв'язки

| Сервіс | Зв'язок |
|---|---|
| **Rukh** | задачі по клієнту й угоді; дошка воронки може спиратися на механіку дошок задач |
| **Wika** | документи клієнта |
| **Doba, Visio** | зустрічі з клієнтом |
| **Questa** | форма заявки → новий контакт |
| **Гості** | замовник як гість workspace |

## 4. Відкриті питання

- Чи будувати воронку на основі дошок Rukh, чи окремо.
- Персональні дані клієнтів: зберігання, експорт, видалення.
- Імпорт контактів.

## Спільні правила для будь-якого нового сервісу

- Це розділ платформи: спільні акаунти, workspace, ролі, підрозділи, гості, сховище, пошук, сповіщення.
- Дані — у таблицях із `workspace_id` і правилами доступу в базі; дві міграції (центральна й командна) плюс перенесення між базами.
- Нові таблиці й правила доступу — окреме погодження власниці до коду.
- Плитка сервісу вже є на стартовій сторінці й лендінгу з позначкою «Скоро» (`src/lib/services.ts`).
- Жодних назв і логотипів сторонніх продуктів.
